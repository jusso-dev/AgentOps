# Product

## Register

product

## Users

AgentOps Playground is for engineering hiring managers, senior engineers, and developer-tool reviewers evaluating whether the portfolio owner understands AI-agent-native software delivery. Users are usually scanning the app on a desktop machine, checking whether the workflow feels credible, runnable, and safe.

## Product Purpose

The product demonstrates how repository-level instructions, MCP boundaries, GitHub context, local persistence, and deterministic agent workflows can produce useful issue triage and changelog outputs without requiring an LLM API. Success means a reviewer can import a repo, generate outputs, inspect the docs, and quickly trust the engineering judgment behind the project.

## Brand Personality

Precise, credible, calm. The interface should feel like a serious developer operations tool: efficient, quietly polished, and careful with security language.

## Anti-references

Avoid marketing-page theatrics, decorative AI glow effects, dark-blue observability dashboard clichés, oversized generic SaaS cards, and playful chatbot styling. The app should not look like a mockup, a template landing page, or an over-decorated AI wrapper.

## Design Principles

- Make the workflow inspectable: show what data was imported, what the agent generated, and where the rules live.
- Earn trust through restraint: use clear hierarchy, stable controls, and explicit safety copy.
- Prefer task flow over spectacle: every polish detail should make importing, triaging, or copying output easier.
- Treat documentation as product surface: repo instructions, MCP examples, and in-app docs carry portfolio value.
- Preserve local-first clarity: make it obvious that tokens are request-scoped and outputs are generated locally.

## Accessibility & Inclusion

Target WCAG AA contrast, keyboard-accessible controls, visible focus states, readable tables, useful empty states, and reduced-motion-friendly transitions.
